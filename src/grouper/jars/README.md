# MS-DRG grouper JARs (not included)

This folder is where the CMS MS-DRG Java grouper goes. The JARs are not part of this repository. You download them from CMS yourself and put them here. Without them the code still runs: fiscal years 2019 to 2022 use the `drgpy` package instead (installed with `pip install -e ".[dev]"`), and encounters without procedure codes use the modal-DRG table (see the top-level `README.md`). With them, FY2023 to FY2026 encounters that carry ICD-10-PCS procedure codes are grouped by the official CMS grouper.

## Why the JARs are not redistributed

The JARs are CMS software, and the terms that govern them are CMS's, not this repository's to grant. This repository therefore does not ship them, their sources or the PDFs that come in the same packages. `.gitignore` excludes `src/grouper/jars/*/`, `src/grouper/vendor/`, `src/grouper/driver/_classes/`, `*.jar` and `*.class`.

One fact about the author's local copies, stated for transparency: the packages for V40.1, V41.0 and V41.1 each include a Word file whose name contains "public domain". The text of each is a dated delivery notice that lists the files in the download. It does not grant a license, and this repository does not rely on it.

## What you need

- A JDK, version 17 or newer, with `java` and `javac` on your `PATH`. A JRE alone is not enough, because the driver is compiled on first use. The code calls `javac --release 17`, and its error messages ask for Java 17 or later. A Java 11 `javac` rejects the flag (`error: release version 17 not supported`). The V43.0 and V43.1 packages and the locally built `gfc-base-api` JAR contain Java 17 class files (class-file version 61); the V40 to V42 packages contain only Java 8 class files (version 52).
- Network access to `cms.gov`, `repo1.maven.org` and `github.com` for the download step below.
- Optionally Maven (`mvn`). The download step builds `gfc-base-api` with Maven when it is installed and with `javac` and `jar` otherwise.

## Getting the JARs

From the repository root, with the Python environment from the top-level README active:

```bash
python -m src.extract.grouper --fy 2026 --version V43.1
```

Other forms that also download V43.1: `--fy-range 2023-2026`, or `--all` for every version below. The V43.1 download is the one the code needs. The grouper puts a `jars/V*` folder on its class path only if the folder holds a file named `msdrg-core-*.jar`, and only the `V43_1` folder does (see "Class path rule" below). The folders for V40.0 to V43.0 are downloaded but are not used. A form that leaves V43.1 out, such as `--fy 2024 --all-versions` (V41.0 and V41.1 only), gives a tree with no usable class path: `src.grouper.grouper` raises `GrouperError: no grouper version directories found`, and `annotate_cohort` falls back to the modal DRG without a note. The command downloads the CMS package for each version, unpacks the inner standalone-JAR archive into `src/grouper/jars/V<major>_<minor>/`, downloads three dependency JARs from Maven Central into `src/grouper/vendor/`, and builds `gfc-base-api` from its GitHub source archive into the same folder. The downloaded archives are kept under `data/bronze/grouper/`, which is not tracked. The download locations are the URLs in `src/config.py` (`GROUPER_SOURCES` for CMS, `GROUPER_RUNTIME_DEPS` for the dependencies). The page where CMS lists the software is the one in `GROUPER_HOME_PAGE_URL` in the same file:

https://www.cms.gov/medicare/payment/prospective-payment-systems/acute-inpatient-pps/ms-drg-classifications-and-software

The code covers eight versions: V40.0 and V40.1 (FY2023), V41.0 and V41.1 (FY2024), V42.0 and V42.1 (FY2025), V43.0 and V43.1 (FY2026). For a given fiscal year the default is the `.0` version; pass `version="V43.1"` to `src.grouper.grouper.assign` to use the April update. CMS file locations change; if a download fails, check the landing page.

## Expected layout

```
src/grouper/
  driver/
    KGCostGrouperDriver.java     tracked; compiled on first use
    _classes/                    generated by javac; not tracked
  jars/
    README.md                    this file
    V40_0/ ... V43_1/            one folder per version; contents below
  vendor/                        four dependency JARs; below
```

`src/grouper/grouper.py` finds everything relative to the repository root. On first use it compiles `driver/KGCostGrouperDriver.java` into `driver/_classes/` (and recompiles when the source is newer than the class file), then starts one long-lived `java` process with a class path made of the JARs described below plus `driver/_classes/`. Requests and answers are one JSON object per line. You do not compile anything by hand. A quick check once the JARs are in place:

```bash
python -m src.grouper.grouper
```

This groups one test claim and prints a line beginning `smoke A419`.

### Class path rule

`_vendored_version_dirs()` in `src/grouper/grouper.py` adds a folder under `jars/` to the class path only if it contains a file matching `msdrg-core-*.jar`. Every JAR in an included folder is added except `*-sources.jar`. The four JARs in `vendor/` are always required, by these exact names: `gfc-base-api-3.4.9.jar`, `protobuf-java-3.25.5.jar`, `slf4j-api-1.7.36.jar`, `slf4j-nop-1.7.36.jar`. The file names inside the CMS packages differ from version to version (table below). In the author's copies only `V43_1` contains a file named `msdrg-core-*.jar`; the other folders hold differently named core JARs. A folder without a matching file is left off the class path. As tested, a copy that held only the `V43_1` folder, `vendor/` and a JDK 17 or newer was sufficient for the FY2023 and FY2024 grouping used in the reproduction check: the `msdrg-core-43.1.0.0.jar` in that folder contains the grouper packages for V40.0 to V43.1, and the other `V*` folders hold no `msdrg-core-*.jar`, so under this rule they are not on the class path.

## Which fiscal years use which path

| Fiscal year of discharge | Grouper | Needs JARs |
|---|---|---|
| FY2023 to FY2026 | CMS Java grouper, V40.0 to V43.0 by default (V40.1 to V43.1 on request) | Yes |
| FY2019 to FY2022 | `drgpy` (pure-Python, versions v36 to v39), because the driver in this repository supports the CMS Java grouper only from V40.0 | No |
| FY2017 and FY2018 | none; the annotator back-translates through the modal-DRG table | No |

The routing is in `assign()` in `src/grouper/grouper.py` and in `GROUPER_VERSIONS_BY_FY` in `src/config.py`.
